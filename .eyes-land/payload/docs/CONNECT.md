# ПОДКЛЮЧЕНИЕ ПРОЕКТА К BILLIONS X EYES

Департамент суверенен: он не знает ни одного проекта в коде. Всё знание о
проекте — в паспорте `adapters/<имя>.json` (ст. 57). Подключение — три
уровня, каждый работает сам по себе.

---
## Уровень 1 · Надзор (обязательный, 1 команда)

В репозитории департамента:

```bash
python3 bin/eyes.py attach --project мойпроект \
    --repo billionsx/мойрепо \
    --prod https://мойдомен.com \
    --globs "src/**/*.css,src/**/*.tsx"
python3 bin/eyes.py projects
git add adapters && git commit -m "eyes — подключён проект мойпроект" && git push
```

Что включается сразу:
- код проекта забирается в `_projects/мойпроект` каждым прогоном;
- советник проходит по глобам и пишет `registry/state/report-мойпроект.md`;
- храповик прибивает долг: он может только падать (рост — красный прогон);
- живой взгляд снимает настоящий DOM с `prod` и `live_pages`;
- 1-го числа выдаётся пиксель-сертификат, 15-го — страж App Store;
- проект появляется в эфире на домене.

**Приватный репозиторий:** в `billionsx/eyes` → Settings → Secrets and
variables → Actions → New repository secret → имя `EYES_PROJECTS_TOKEN`,
значение — fine-grained PAT с `Contents: Read` на этот репозиторий.

---
## Уровень 2 · Ревью каждого PR (1 файл в репо проекта)

Скопировать [`../templates/eyes-client.yml`](../templates/eyes-client.yml)
в репозиторий проекта как `.github/workflows/eyes.yml` и подставить два
значения — `project` и `globs`. Ни submodule, ни GitHub App, ни секретов
не нужно: департамент приходит сам на каждый pull request и оставляет
построчные замечания числами своих законов.

**Проект не работает через PR?** Тогда вместо этого файла (или вместе с ним)
скопировать [`../templates/eyes-client-push.yml`](../templates/eyes-client-push.yml)
как `.github/workflows/eyes-watch.yml`. Департамент придёт на каждый пуш и
оставит комментарий к коммиту с адресами находок. Секретов по-прежнему не
нужно. Сборку проекта он не роняет, а на чистых коммитах молчит: вердикт
виден в журнале прогона, комментарий появляется, только когда есть что
сказать.

## Уровень 3 · Монитор после деплоя (1 файл + 1 секрет в репо проекта)

Скопировать [`../templates/ping-eyes.yml`](../templates/ping-eyes.yml) как
`.github/workflows/ping-eyes.yml`, вписать в `workflows:` точное поле
`name:` своего деплой-воркфлоу и добавить секрет `EYES_DISPATCH_TOKEN`
(fine-grained PAT, `Contents: Read` + `Metadata: Read` на `billionsx/eyes`).

После каждого успешного деплоя проект будит монитор департамента; тот
смотрит на свежий прод живыми глазами и сравнивает с базовой линией:
`НОВОЕ` — регресс (алерт), `ЗАКРЫТО` — подтверждённая починка. Без этого
файла монитор всё равно работает — по расписанию каждые 6 часов.

## Паспорт проекта — поля

| поле | смысл |
|---|---|
| `project` | имя (совпадает с именем файла) |
| `enabled` | `false` → паспорт есть, но проект не обслуживается |
| `repo` | `owner/name` — откуда забрать код |
| `branch` | ветка (по умолчанию `main`) |
| `prod` | корень прода |
| `live_pages` | страницы живого взгляда (пусто → берётся `prod`) |
| `deploy_workflow` | имя воркфлоу деплоя проекта |
| `report.globs` / `report.rules` | что смотрит советник |
| `strict.globs` / `strict.rules` | что валит сборку |
| `allow_extra`, `sizes_extra`, `radius_extra` | законные исключения проекта |

Проект по умолчанию: переменная `EYES_PROJECT` → файл `adapters/DEFAULT` →
единственный включённый паспорт → `adapters/default.json`.

---
## Отключить проект, не теряя историю

В паспорте поставить `"enabled": false` — реестры, отчёты и сертификаты
остаются на месте, департамент больше не забирает код и не судит.
